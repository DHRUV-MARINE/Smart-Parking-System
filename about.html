How SmartParking works

An academic Data Structures & Algorithms project: the website is the demo, the C++ backend is the subject.

Project overview

SmartParking is a smart parking management system. Users search for parking near a location, compare prices and free slots, then reserve a specific slot. Availability changes the moment a booking is made or cancelled.

The important part is where the logic runs: all search, filtering, sorting, shortest-path and availability work is implemented in C++ using data structures written by hand. The browser only sends HTTP requests and paints the JSON it gets back. No parking algorithm runs in JavaScript, and no SQL is used for sorting or shortest paths.

How each algorithm works

Dijkstra's shortest path

Every landmark, junction and parking entrance is a vertex. Roads are two-way edges with a weight in kilometres. Starting from the user's nearest vertex, the algorithm keeps a distance array, pushes the source into a min-heap and repeatedly settles the closest unvisited vertex, relaxing its neighbours. Manual binary-heap siftUp / siftDown code is in graph.h; the road path is rebuilt from the parent array filled by dijkstra().

Merge sort

Recursively splits the result array in half, sorts each half, then merges them with a buffer. Stable, so lots with the same distance keep a sensible order.

Quick sort

Partition around a median-of-three pivot and recurse on both sides. Used for price ordering because it sorts in place.

Hash table

HashTable<Key, Value, Hasher> hashes the key, takes it modulo the bucket count, and stores the entry at the head of that bucket's chain. It rehashes when the load factor passes 0.75, which keeps lookup at O(1) on average.

Binary search and prefix search

Lot names are lowercased and kept in sorted order. An exact match is found with binary search; a prefix is found with a lower-bound search followed by a forward scan; area and address use a substring scan as a fallback.

Waiting list queue

A full lot keeps a FIFO queue with front and back pointers. When a booking is cancelled, the slot is freed and the first waiter is dequeued and automatically booked into it.

Run it locally

cd SmartParking
g++ -std=c++17 -O2 -Ibackend/third_party backend/*.cpp backend/third_party/sqlite3.c -o smartparking
./smartparking --port 8080
# open http://localhost:8080

On Windows 11 with MinGW, double-click build.bat and run smartparking.exe --port 8080. The SQLite library is vendored in backend/third_party, so there is nothing else to install apart from the compiler. Full step-by-step instructions are in README.md.

Benefits of this design

  • One source of truth: availability is stored per slot in SQLite, so a restart never leaves the numbers wrong.
  • Fair waiting lists: a queue guarantees first-come, first-served promotion instead of a race between users.
  • Honest distance: road-graph distances beat straight-line distance when comparing parking lots.
  • Separation of concerns: the browser cannot compute or fake a distance or a price — the C++ backend decides.
